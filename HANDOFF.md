# Контекст проекта: тренажёр корейского языка (단어장)

Загрузи этот файл + текущий `korean-flashcards.html` в начале новой сессии и попроси
Claude продолжить разработку / разбить на файлы для GitHub Pages.

## Что это

Одностраничное веб-приложение (чистый HTML/CSS/JS, без фреймворков и сборки) —
персональный тренажёр корейского языка для пользователя (TOPIK I, курсы при
университете Инха). Сейчас всё лежит в одном файле `korean-flashcards.html`
(~605 КБ), открывается двойным кликом, работает офлайн, без сервера.

**Задача следующей сессии:** разбить этот файл на несколько (HTML/CSS/JS/JSON)
и подготовить к публикации на GitHub Pages.

## Почему один файл и что изменится при разбиении

- Сейчас файл самодостаточен: открывается через `file://` без сервера.
- Если разбить на отдельные файлы (`app.js`, `style.css`, `words.json` и т.д.),
  то `fetch()`/загрузка JSON с локального диска будет заблокирована CORS —
  **работать будет только через HTTP-сервер** (или сразу на GitHub Pages).
- Значит: разбиение стоит делать одновременно с публикацией на GitHub Pages,
  а не раньше — иначе пользователь не сможет открыть файл локально для проверки.

## Структура текущего файла

Один HTML-файл, внутри:

1. `<style>...</style>` — CSS, ~11 КБ. Дизайн-система: тёплая бумажная палитра
   (`--paper`, `--ink`, красный/синий акцент в духе тхэгыка), карточки, панели
   с шевроном (категории/подтемы), `.qcard`/`.opt`/`.sent-blank` и т.д.
2. Пять `<script type="application/json" id="...">` блоков с данными (см. ниже).
3. Один большой `<script>...</script>` с логикой приложения, ~81 КБ JS
   (без фреймворков, ванильный JS, рендер через `innerHTML = html` + делегирование
   обработчиков в `attachHandlers()`).

## Данные (JSON-блоки) — с чего начинать разбиение на файлы

| id в HTML          | Предлагаемое имя файла | Размер   | Содержимое |
|---------------------|------------------------|----------|------------|
| `words-data`        | `data/words.json`      | ~288 КБ  | 39 категорий, 1308 слов. У каждого слова: `kr`, `translit`, `meaning`, `notes`, `related` (антоним/синоним или null), `examples: [{kr, ru, form}]`. Поле `form` — точная подстрока в `kr`, которая вырезается как пропуск в упражнениях «предложение». **100% слов имеют рабочий пример** — это специально проверялось и чинилось несколько раз, не трогать без валидации (`form` должно быть точной подстрокой `kr`, иначе упражнение сломается). |
| `grammar-data`       | `data/grammar.json`    | ~11 КБ   | 11 тем грамматики (справочник), 82 конструкции с уроком (1-16과), группой, описанием. |
| `grammar-ex-data`    | `data/grammar-exercises.json` | ~13 КБ | 50 упражнений «вставь правильную форму», у каждого `cat`, `lesson: [числа]`, `before/after/options/correct/ru/note`. |
| `exam-data`          | `data/exam.json`       | ~6 КБ    | Раздел «Экзамен»: `reading`(8), `ordering`(6), `construct`(8), `cloze`(5) — авторский контент в стиле TOPIK I (не скопирован из интернета). |
| `qa-data`            | `data/qa.json`         | ~9 КБ    | Раздел «Вопросы»: `qword`(30, вопросительные слова), `qanswer`(16, подбор ответа по типу вопроса), `response`(16, да/нет/связки). |
| `theme-data`         | `data/theme.json`      | ~32 КБ   | Раздел «Темы»: `counters`(85!), `datetime`(18), `honorific`(24), `position`(20), `irregular`(64). |

Итого данных ~360 КБ, кода ~92 КБ (JS+CSS). При разбиении данные почти не сжимаются
дополнительно (уже компактный JSON без отступов) — расчёт объёма загрузки не изменится
сильно, выигрыш в основном в кешировании и удобстве редактирования.

## Архитектура JS (важно понимать перед правками)

- **Нет фреймворка.** Один глобальный объект `state`, один `render()`, который
  строит HTML-строку целиком и делает `root.innerHTML = html`, затем
  `attachHandlers()` навешивает обработчики заново (делегирование через
  `document.querySelectorAll`).
- **Навигация:** `state.view` — одно из `session|words|grammar|exam|qa|theme|search`.
  Верхнее меню — иконки (SVG, инлайн, только `rect/circle/line/polyline/text`,
  без сложных path — сделано специально для надёжности рендера).
- **Каждый раздел независим:** переключение `state.view` НЕ сбрасывает состояние
  других разделов — можно уйти в «Поиск» посреди сессии/темы и вернуться на то же
  место (это специально тестировалось).
- **Общая система вопросов:** у каждого раздела своя фабрика вопросов
  (`qCard`, `qKr2Ru`, `qThemeCloze`, `qGrammar`, ...) и свой `reset*Queue()` +
  `rebuild*Question()`. Ответ обрабатывается через `handleChoice()` (множественный
  выбор) или `handleTypeSubmit()` (ввод текста) — эти функции разветвляются по
  `q.type` и умеют работать в контексте сессии (`state.view === 'session'`) и
  вне её.
- **Прогресс слов** (`state.progress`, known/learning по `word.id`) — персистентный
  через `window.storage` (API артефактов Claude, не localStorage!). Обновляется
  через `markWord(id, status)` + `saveProgress()`.

## Разделы приложения (для справки)

1. **Сессия** — главный тренировочный режим. Выбор темы (1 из 16 уроков — своя карта
   `LESSON_CATEGORIES`, категория→урок) ИЛИ категории слов (взаимоисключимо),
   количество слов 10/20/30, и порядок: «По этапам» (последовательно) или
   «Вперемешку» — это НЕ простое перемешивание, а адаптивный алгоритм:
   карточки партиями по 10 (с закреплением предыдущих партий), до безошибочного
   прохождения каждой партии (mastery-loop: неверный ответ — в конец очереди,
   верный — убирается), затем общая фаза «до идеала» по всем словам всеми
   типами заданий сразу.
2. **Слова** — карточки/слово→перевод/перевод→слово/предложение(выбор)/написание/
   предложение(ввод)/антонимы-синонимы. Фильтр категорий + выпадающая панель
   выбора упражнения (стиль как у категорий — `panel`+`cat-grid`+`cat-chip`,
   НЕ нативный select и НЕ отдельный стиль).
3. **Грамматика** — Справочник (список) + Тренировка (49 упражнений, фильтр по теме).
4. **Экзамен** — Чтение/Порядок/Составь/Вставь (авторский контент).
5. **Вопросы** — вопросительные слова / подбор ответа / да-нет-связки.
6. **Темы** — Счётные слова / Даты и время / Уважительно / Место / Неправильные
   глаголы. У «Счётных слов» отдельно 4 режима (Выбор/Впишите/Переведите/Смешанный)
   и особая логика: пул 85 заданий на 20 слов, при каждом заходе/сбросе выбирается
   **по 2 случайных задания на каждое слово** (см. `buildPerAnswerSample()`).
7. **Поиск** — живой поиск по словарю (кор./транслит/рус.), с примером и
   антонимом/синонимом в результате.

Везде есть маленькая круглая кнопка-иконка (↻) — сброс+перемешать; в разделе
«Слова» она ещё чистит прогресс (`known`/`learning`) только для выбранных сейчас
категорий, не трогая остальной словарь.

## Как я тестирую изменения (важно повторять в новой сессии!)

Правки в HTML-файле делаются через `str_replace`/`python re` прямо в
`/mnt/user-data/outputs/korean-flashcards.html`. После каждой правки:

1. Извлекаю `<script>` блоки регэкспом, `node --check` на JS-код (синтаксис).
2. Патчу извлечённый JS: заменяю `loadProgress();\n})();` в конце IIFE на
   версию, которая ещё экспортирует нужные функции в `window.__test = {...}`
   (внутренние функции недоступны снаружи IIFE иначе).
3. Пишу headless Node-тест: подделываю `window.storage`, `document.getElementById`
   (возвращает объект с `textContent` = соответствующий JSON), `document.createElement`,
   `document.querySelectorAll` (возвращает `[]`, т.к. обработчики не нужны в тесте).
4. Прогоняю сценарии: полный цикл по каждому разделу/подтеме (отвечаю на все
   вопросы, включая через `while` с guard-лимитом на случай бесконечного цикла),
   плюс точечные проверки (структура данных, покрытие примерами, персистентность
   состояния при переключении вкладок).

**Частые баги, которые ловились именно тестами:** пропуск в `word.examples[].form`
не найден в `kr` (регэксп/копипаст ошибка); категория задания не совпадает по имени
между справочником и упражнением (фильтр находит 0); забытый `state.view = 'session'`
в тесте (не баг приложения, а баг теста — но выглядит как зависание); дубли/пропуски
при парсинге markdown с грамматикой (тире без пробела — часть пунктов тихо терялась).

## Что уже сделано (хронология функций, если нужно быстро сориентироваться)

Словарь → грамматика (справочник+тренировка) → раздел «Экзамен» → «Вопросы» →
навигация иконками + единый стиль выпадающих панелей → «Темы» (счётные/даты/
уважительно/место) → тема «Неправильные глаголы» (все 50 слов словаря, не
выборочно) → полный аудит слов из ВСЕХ упражнений на предмет отсутствия в
словаре (нашли и добавили ~95 слов в несколько заходов) → сессия «вперемешку»
(адаптивный алгоритм) → маленькая кнопка сброса-иконка везде → счётные слова:
+60 заданий, логика «2 на слово», 4 режима ответа (выбор/впишите/переведите/
смешанный).

## Задача на разбиение файлов — предложение по структуре

```
/
├── index.html          (разметка + <link>/<script src> на остальное)
├── style.css
├── app.js               (вся логика — один файл, ~81 КБ, можно оставить одним)
├── data/
│   ├── words.json
│   ├── grammar.json
│   ├── grammar-exercises.json
│   ├── exam.json
│   ├── qa.json
│   └── theme.json
└── README.md
```

Технически: заменить `<script id="words-data" type="application/json">...</script>`
на `fetch('data/words.json').then(r=>r.json())` и т.п. — придётся сделать
`loadProgress()`/инициализацию асинхронной (сейчас она уже `async function`,
т.к. ждёт `window.storage.get`, так что паттерн `await Promise.all([...fetch...])`
встроится туда естественно). **`window.storage` — API артефактов Claude, на
GitHub Pages его не будет** — для персистентности прогресса на GitHub Pages
нужно будет заменить на `localStorage` (это единственное существенное отличие
рантайма между «артефакт Claude» и «статический сайт»).

## Важные ограничения/договорённости, которые стоит соблюдать дальше

- Никогда не копировать текст упражнений из реального интернета дословно —
  весь контент «Экзамена»/«Тем»/«Вопросов» — авторский, в стиле TOPIK, но не
  скопированный (принципиальное ограничение, уже проговаривалось с пользователем).
- Любое новое слово в словаре — сразу с `examples: [{kr, ru, form}]`, `form`
  обязательно проверять как точную подстроку `kr` (иначе тихо сломается только
  в режиме «предложение», легко пропустить).
- Названия категорий должны быть idempotent между `words.json` и
  `LESSON_CATEGORIES`/`SHORT_NAMES` — при добавлении новой категории не забыть
  завести короткое имя (если длинное) и решить, к какому уроку её привязать
  (или сознательно не привязывать, как «Бизнес и экономика»).
